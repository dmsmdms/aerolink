# 03. USB link (RP2040 ↔ phone)

Protocol version: **1**. Reference frames: `protocol/vectors.txt` (generated by `tools/gen_vectors.py`);
the firmware and Android codecs are both tested against it.

## Transport: Android Open Accessory (AOA)

- `LINK-001` The RP2040 is the USB **host** (TinyUSB host stack, full speed 12 Mbit/s); the phone is the
  USB **device** in accessory mode. The phone needs no USB host/OTG support and no third-party drivers.
  AOA 1.0 is available on every supported Android version (6.0+).
- `LINK-002` Accessory start sequence (host side), on every phone attach:
  1. `GET_PROTOCOL` (vendor IN request 51) — must return ≥ 1.
  2. `SEND_STRING` (request 52) for index 0..5: manufacturer `AeroLink`, model `RobotBase`,
     description `AeroLink robot base`, version (firmware version), URI (project URL), serial (RP2040 unique board id).
  3. `START` (request 53). The phone re-enumerates as VID `0x18D1`, PID `0x2D00` (or `0x2D01` with adb).
  4. Open interface 0: one bulk IN + one bulk OUT endpoint (64-byte packets).
- `LINK-003` The Android app declares an `accessory_filter.xml` matching manufacturer/model, so the system
  starts it on attach. The "use by default" choice is made once during robot provisioning.
- `LINK-004` VBUS for the phone comes from the robot 5 V rail (see [04](04-power.md)).

## Framing

- `LINK-010` On the wire every frame is COBS-encoded and terminated by `0x00`, so it survives arbitrary
  splitting/merging into USB packets. Decoded frame layout:

  | Offset | Size | Field |
  |--------|------|-------|
  | 0 | 1 | `type` |
  | 1 | 1 | `seq` |
  | 2 | n | payload (0..60 bytes) |
  | 2+n | 2 | CRC-16, little-endian |

- `LINK-011` CRC-16/CCITT-FALSE (poly `0x1021`, init `0xFFFF`, no reflection, no xorout) over `type..payload`.
  Multi-byte fields are little-endian, signed values are two's complement.
- `LINK-012` Max decoded frame is 64 bytes (max encoded 66 incl. delimiter). Frames with bad CRC, wrong length
  for their type, or unknown type are dropped and counted (`rx_errors` in TELEMETRY), never acted upon.
  An over-long frame is discarded up to the next delimiter.
- `LINK-013` `seq` is a per-sender wrapping counter. Replies (HELLO_ACK, PONG, NACK) echo the `seq` of the
  request they answer; spontaneous firmware frames (TELEMETRY, EVENT) carry the firmware's own counter.

## Messages

`P→F` phone to firmware, `F→P` firmware to phone. Types `0x01–0x1F` / `0x81–0x9F` are the core set,
`0x20–0x3F` / `0xA0–0xBF` are reserved for robot peripherals (cargo lock, lid sensor, lights, range
sensors — announced via `caps`).

| Type | Dir | Name | Payload | Len |
|------|-----|------|---------|-----|
| 0x01 | P→F | HELLO | `proto_version:u8` | 1 |
| 0x02 | P→F | ARM | — | 0 |
| 0x03 | P→F | DISARM | — | 0 |
| 0x04 | P→F | DRIVE | `speed:i16` ‰ of max (−1000..1000, + forward), `steer:i16` ‰ (−1000..1000, + right), `source:u8`, `ttl_ms:u16` | 7 |
| 0x05 | P→F | PING | — | 0 |
| 0x06 | P→F | CONFIG | `max_speed:u16` ‰, `accel:u16` ‰/s, `telemetry_period_ms:u16` (0 = events only), `cmd_timeout_ms:u16` | 8 |
| 0x07 | P→F | REBOOT_BOOTSEL | `magic:u32` = `0x544F4F42` ("BOOT") | 4 |
| 0x81 | F→P | HELLO_ACK | `proto_version:u8`, `fw_major:u8`, `fw_minor:u8`, `fw_patch:u8`, `caps:u32`, `board_id:8×u8` | 16 |
| 0x82 | F→P | TELEMETRY | `state:u8`, `faults:u16`, `battery_mv:u16`, `speed_l:i16` ‰, `speed_r:i16` ‰, `temp_dc:i16` (0.1 °C), `rx_errors:u16` | 13 |
| 0x83 | F→P | EVENT | `code:u8`, `arg:u16` | 3 |
| 0x84 | F→P | NACK | `rejected_type:u8`, `reason:u8` | 2 |
| 0x85 | F→P | PONG | — | 0 |

Unknown values: `battery_mv = 0`, `temp_dc = −32768`.

## Behaviour

- `LINK-030` After the accessory is opened the phone sends HELLO; the firmware answers HELLO_ACK. If the
  major protocol versions differ the phone shows an error and never ARMs.
- `LINK-031` ARM is accepted only in DISARMED with no active faults (otherwise NACK). DISARM is always accepted.
  Every state change emits `EVENT STATE`.
- `LINK-032` DRIVE is accepted only in ARMED (otherwise silently dropped — no NACK flood at 20 Hz). Values out
  of range are clamped. A DRIVE is valid for `min(ttl_ms, cmd_timeout_ms)`.
- `LINK-033` CONFIG may arrive in any state; values are clamped to the firmware maxima ([05](05-safety.md)).
- `LINK-034` REBOOT_BOOTSEL is accepted only in DISARMED with the correct magic.

## Traffic budget

- `LINK-020` **DISARMED: zero periodic traffic.** Only EVENT frames on change (fault, state).
- `LINK-021` **ARMED:** DRIVE at 20 Hz from the phone, TELEMETRY at `telemetry_period_ms` (default 200 ms).
- `LINK-022` The phone never polls USB: one coroutine blocks on a bulk read; no timers in the read path.
